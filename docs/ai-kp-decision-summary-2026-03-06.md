# AI-KP 决策摘要（2026-03-06）

> 这份文档用于沉淀目前已经和用户确认过的关键方向，避免后续实现时跑偏。

## 1. 项目定义

- `AI-KP` 中的 `KP` 指 `TRPG / CoC 主持人（Keeper）`。
- 目标不是普通陪聊，而是一个可运行的 `AI 跑团主持系统`。
- 首版规则基线采用 `Call of Cthulhu 7th Edition`。

## 2. 总体架构路线

采用双层结构：

1. `core engine`：
   - 规则判定
   - 场景状态机
   - 角色卡与存档
   - 线索、事件、时间推进
   - 软裁定与后果生成

2. `adapter / plugin`：
   - 接聊天平台消息
   - 路由到核心引擎
   - 处理群号、会话、权限、限流
   - 将结果回发到聊天入口

结论：
- 先做核心引擎，后包插件接入。
- 不把首版实现直接绑死在单一聊天平台上。

## 3. 规则与体验原则

### 3.1 核心体验
- 玩家的自然语言探索要尽量都能接住。
- 不做生硬的“前方区域以后再来吧”。
- 面对越界或离谱行动，优先转成世界内后果，而不是机械拒绝。
- KP 与玩家同侧：目标是推进故事并尽量活着结团。

### 3.2 规则原则
- 硬规则明确：检定、伤害、SAN、回合等要有稳定边界。
- 软规则开放：不穷举玩家脑洞，而是穷举裁定方法。
- 护栏控平衡：过强效果可以被降档、加代价、缩持续时间。

### 3.3 失败处理
- 采用 `fail forward`：失败也推进剧情。
- 失败后优先给：
  - 时间代价
  - 暴露风险
  - 资源损失
  - 关系恶化
  - 偏差信息

## 4. 玩家主视角流程

当前确认的玩家一般流程：

1. 团前说明
2. 车卡
3. 背景确认与锁卡前微调
4. 携带物品选择（时代约束 + 灵活配额）
5. 进入游戏
6. 探索 / NPC 对话 / 线索获取
7. 时间推进与风险提醒
8. 战斗或危机处理
9. 结果分流与继续探索
10. 结团结算与存档

补充共识：
- 物品选择需要考虑时代背景。
- 强力物品少量、日常物品较灵活。
- 玩家作死时，KP 可先用“你确定吗”做友好提醒。
- 动态援军、地形利用、临场脑洞都应该纳入裁定，而不是被硬拦。

## 5. 裁定方法论

软裁定不靠穷举动作名，而靠一套统一框架：

1. 玩家意图是什么
2. 依据是什么（职业、技能、环境、前置行为）
3. 影响有多大
4. 代价是什么
5. 持续多久
6. 是否破坏平衡

例如：
- 歌手在战斗中唱歌鼓舞队友，不需要预写“唱歌 buff 规则”。
- 引擎应根据角色设定、场景、风险和强度，为其给出一个合理但受控的效果。
